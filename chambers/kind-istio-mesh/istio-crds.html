Istio CRDs
the mesh configuration surface

Every Istio behavior is a custom resource that istiod compiles into Envoy config and pushes to the proxies over xDS. Your app makes plain calls; these objects decide how traffic is routed, secured, and observed. Grouped by concern, with purpose, the core idea, what it can do, and where in the request it acts.

The machine

Two planes, one control loop

The data plane is an Envoy proxy beside every workload; the control plane (istiod) watches Kubernetes and these CRDs, mints workload certificates, and streams config to the proxies. Nothing here touches application code.

Traffic management

networking.istio.io - routing, resilience, and the mesh's service registry. This is where canary, blue-green, retries, and circuit breaking live.

Gatewaynetworking/v1

Opens ports and hosts on a standalone edge Envoy (ingress or egress).

The door, not the router. It says "accept HTTP on :80 for these hosts"; a VirtualService bound to it decides where that traffic goes.

Can do
ports + protocolsTLS terminationhost / SNI match
Acts at · edge gateway proxy
# :80 HTTP, any host
servers: [{ port: {number: 80, protocol: HTTP}, hosts: ["*"] }]
VirtualServicenetworking/v1

The L7 routing rulebook: match requests, then decide what happens to them.

Everything about a request's path in one place. Split by weight for canary, flip for blue-green, and add resilience and testing behaviors.

Can do
weighted splitretriestimeoutsfault injectmirrorheader / URI rewrite
Acts at · client-side proxy + gateway
route:
  - { destination: {host: web, subset: v1}, weight: 90 }
  - { destination: {host: web, subset: v2}, weight: 10 }
DestinationRulenetworking/v1

Policy for a destination after routing has chosen it: subsets, LB, pooling, health.

Defines the named subsets (v1/v2 by label) that VirtualService routes to, plus how to talk to them.

Can do
subsetsload-balancerconnection pooloutlier detectionupstream TLS
Acts at · client-side proxy
subsets:
  - { name: v1, labels: {version: v1} }
  - { name: v2, labels: {version: v2} }

Security

security.istio.io - zero-trust in three layers: is the transport encrypted (Peer), is the end-user who they claim (Request), and is this caller allowed (Authorization).

PeerAuthenticationsecurity/v1

Sets the mutual-TLS mode for workload-to-workload traffic.

"Is it really the calling service, over an encrypted channel." STRICT accepts only mTLS; PERMISSIVE accepts both so you can migrate a live system with no downtime, then flip.

Can do
STRICTPERMISSIVEDISABLEper-port mode
Acts at · server-side proxy
mtls: { mode: STRICT }
RequestAuthenticationsecurity/v1

Validates end-user credentials (JWTs) on incoming requests.

Origin auth, separate from workload mTLS. It verifies a token's issuer + signature (JWKS) and exposes its claims for AuthorizationPolicy to act on. It rejects bad tokens but does not require one on its own.

Can do
JWT verifyJWKS / issuerclaims → policy
Acts at · server-side proxy (L7)
jwtRules:
  - { issuer: "https://accounts.example.com", jwksUri: ... }
AuthorizationPolicysecurity/v1

Allow / deny rules on who may call what, at L7.

The "can they" layer on top of "are they." Match on source identity (SPIFFE), namespace, method, path, or JWT claims; default-deny once any ALLOW policy exists on a workload.

Can do
ALLOW / DENYby identity + claimmethod + pathCUSTOM (ext authz)
Acts at · server-side proxy
action: ALLOW
rules: [{ from: [{source: {principals: ["*/ns/web/*"]}}] }]

The mental model

Four sentences that untangle it

The names overlap in the docs; these hold the shape.

VirtualService = routing

What happens to a request: match, split, retry, timeout, mirror.

DestinationRule = the pool

Policy for what you routed to: subsets, load balancing, circuit breaking.

Gateway = the edge

Opens the port/host. Routing still comes from a VirtualService.

Peer / Authz = security

Peer proves it is really them (mTLS); Authorization decides if they may.

Two things to know beyond the list.
The Kubernetes Gateway API (gateway.networking.k8s.io: Gateway, HTTPRoute) is the vendor-neutral standard Istio also implements, and the direction for new setups; classic Gateway + VirtualService stays feature-rich. In ambient mode there are no sidecars: a per-node ztunnel does L4 + mTLS, and L7 features run in a waypoint proxy provisioned through the Gateway API. Same control plane, same security and routing intent, a lighter data plane.
